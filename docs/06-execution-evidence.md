# Execution Evidence — StudentFX

This folder contains proof that StudentFX actually runs. Because the project is
**not on-chain** (it is a sandbox that models PKR→CNY transfers), the evidence
is a transcript of a simulated-account session plus the supporting logs and
tests, and a short screen recording.

Everything here was produced by running the real code. `docs/evidence/` was
generated by `scripts/capture_evidence.py`, which drives a scripted session
through the real ASGI app (real middleware, real sandbox ledger, real
hash-chained audit log).

---

## 1. Files in this evidence pack

| File | What it proves |
|---|---|
| `evidence/session-transcript.txt` | A full request/response walkthrough of the running system: login, quote comparison, transfer request → confirm, request → reject, expense, spending summary, forecast, quote check, chat, audit log, logout. |
| `evidence/audit-log.jsonl` | The four tamper-evident audit entries produced by the session. |
| `evidence/audit-verification.txt` | The result of re-verifying the hash chain: `OK (chain intact)`. |

| `evidence/dashboard.png` | The live web UI rendering real server data (rate, wallets, tier, route comparison, audit status). |

`docs/evidence/` is committed, so it is visible directly on GitHub. It is also
regenerable at any time (see §4).

## 2. Highlights from the transcript

Run environment: Python 3.14.0 on Windows, mid-market rate
**1 CNY = 41.392442 PKR** (source `open.er-api.com`, as of
`Mon, 19 Oct 2026 00:02:32 +0000`).

**Access control works** — step 1, before signing in:

```
GET /api/state   →  401  {"detail": "Please sign in."}
```

**Comparing routes** (step 4), the core algorithm in action for 8000 CNY:

| Route | Total PKR | Effective rate | Hidden cost |
|---|---|---|---|
| ICBC Pakistan TT → ICBC China | 334,174.28 | 41.7718 | 3,034.74 PKR (0.92%) |
| ICBC Pakistan TT → another bank | 334,240.51 | 41.7801 | 3,100.97 PKR (0.94%) |
| Bank Alfalah outward remittance | 339,449.02 | 42.4311 | 8,309.48 PKR (2.51%) |

**The tier system works** (steps 5–8). At tier 1 the AI/user can only *draft*:

```
request_transfer 3000 CNY  →  status "pending_confirmation"  ("tier 1: drafts only, user must confirm")
POST /api/confirm/T0001   →  status "executed"               ("confirmed by user")
request_transfer 5000 CNY  →  status "pending_confirmation"
POST /api/reject/T0002    →  status "rejected"               ("rejected by user")
```

**Balances moved only on confirm**: PKR went `2,000,000 → 1,872,953.50`, CNY
went `0 → 3,000`. The rejected draft changed nothing.

**Spending and forecast** (steps 9–12): a 25 CNY lunch summarised as
`1,034.81 PKR` at mid-market; a 1,800 CNY rent obligation in 5 days gave a
minimum balance of `1,200 CNY` on `2026-10-24` with **no shortfall**.

**Quote check** (step 13): 100,000 PKR → 2,350 CNY implies an effective rate of
`42.5532` against a mid of `41.392442`, i.e. **2,727.76 PKR (2.80%)** hidden.

**Chat** (step 14): asked for the cheapest way to send 9000 CNY, the assistant
called `compare_routes` and answered with the ICBC route and its fee source —
numbers sourced from the tool, not invented.

**Logout works** (steps 16–17):

```
POST /api/logout  →  200
GET  /api/state   →  401
```

## 3. Audit trail and tamper-evidence

The session produced four chained entries. Each entry carries the hash of the
previous one:

```
request  T0001  prev ""                                                                 
confirm  T0001  prev e3a1bc2b08a3…   (hash 992e3a5dc3fc…)
request  T0002  prev 992e3a5dc3fc…
reject   T0002  prev b82bc5b8a8ce…
```

`audit-verification.txt` records the result of recomputing the chain:

```
audit-log.jsonl hash-chain verification
entries: 4
result: OK (chain intact)
```

The app also re-verifies this chain at most every 30 seconds while running and
flips `audit_ok` in the UI if it ever breaks.

## 4. Reproducing the evidence

```powershell
# 1. Set up (see README for full deployment steps)
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 2. Regenerate the evidence pack (needs internet once, for the live rate)
.venv\Scripts\python.exe scripts\capture_evidence.py

# 3. Run the tests
.venv\Scripts\python.exe -m pytest -q > docs\evidence\tests.txt
```

`capture_evidence.py` uses the offline `MockModel`, so it runs without any AI
API key.

## 5. Demo video

A short screen recording accompanies this evidence pack. Because the recording
must be captured on a machine with a visible desktop, it is provided alongside
the submission rather than committed here.

**What the recording shows (≈3 minutes):**

1. `pip install` and `pytest` — **150 passed**.
2. Start the server:
   `python -m uvicorn server:app --host 127.0.0.1 --port 8000`
   and note the startup line and (if `ACCESS_TOKEN` is unset) the security
   warning.
3. Open `http://127.0.0.1:8000`, sign in with the access token (wrong token first to show it is rejected).
4. Change the tier to 1 (draft only); in **Compare Routes**, compare 8000 CNY and
   show the route cards, the hidden-cost figures and each fee source. Request a
   transfer and show it landing in **Waiting for your confirmation**.
5. Press **Confirm** and show the wallets update; create another and **Reject**
   it to show nothing moves.
6. Add an expense and show the monthly summary; add a rent event and run the
   forecast to show the "transfer by" date.
7. Ask the assistant (in plain language) for the cheapest ways to send money —
   it answers with tool-sourced figures, and the reply shows the real tool trace.
8. Show the audit log growing, the audit "verified" chip, and the live clock.

The UI is fully wired to the API: every number and every button in the recording
comes from the running server, not from the page. `docs/evidence/dashboard.png`
is a still of the same screen.
